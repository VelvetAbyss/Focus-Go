# Focus&go × Notion 交互基准与实施记录

> 2026-09-29。目标来自用户：“全面学习 Notion 的交互”，让 Focus&go 的交互质量至少达到 Notion。本文是研究与实施基准，不代表已达到该水平。用户已确认优先按个人工作流的交互质量验收；完整通用数据库构建器与多人实时协作不在本轮验收范围内。

## 研究口径

比较的是用户完成工作时的连续体验：捕捉 → 找回 → 组织 → 执行 → 回顾，以及误操作后的恢复。Notion 的界面或代码无需照搬。Focus&go 以 Task Execution 为核心，Project 组织目标，Note 保存上下文；这一领域边界见 [domain-boundaries.md](domain-boundaries.md)。

资料为 2026-09-29 查阅的 Notion 官方帮助文档、开源项目官方仓库、当前本地代码和独立的空数据浏览器预览。没有登录 Notion 账户做并排任务计时，也没有读取用户 Chrome 的真实数据；下表中的“待实测”不可当作缺失。

## Notion 值得学习的交互机制

| 机制 | 用户获得的能力 | 官方证据 |

| 键盘优先编辑 | `/` 插入块，常用 Markdown / 键盘快捷键，Esc 退出菜单 | [快捷键](https://www.notion.com/help/keyboard-shortcuts)、[写作与编辑](https://www.notion.com/help/writing-and-editing-basics) |
| 直接操作内容 | 块手柄提供移动、转换和上下文操作；页面可嵌套，侧栏可拖拽重排 | [删除与恢复](https://www.notion.com/help/duplicate-delete-and-restore-content)、[侧栏](https://www.notion.com/help/navigate-with-the-sidebar) |

## 实施顺序

### P0：建立真实验收基线

1. 用固定的匿名样本数据覆盖 50 个任务、10 个项目、30 篇笔记及常见长文，不碰用户数据。
2. 录下 6 条核心旅程的点击数、耗时、失误点与键盘路径：新建任务；找回笔记；从笔记建任务；项目内完成并撤销；跨视图修改同一任务；离线编辑后恢复。
3. 检查 1280–1920px 桌面、窄屏、中文/英文、浅色/深色、键盘及 reduced motion；分别记录开发构建和生产构建结果。
4. 先修复会造成数据丢失、状态不一致、错误恢复失败的缺陷。

### P1：让工作流连起来

1. 统一全局导航：最近访问、收藏、内容层级、搜索结果预览和明确的返回路径；保留现有 ⌘K 与模块侧栏。
2. 所有对象使用稳定深链接，让刷新、前进/后退、从搜索进入详情后返回都能保留上下文。
3. 捕捉入口统一调用 Task 应用服务，避免仪表盘、笔记、项目各自定义任务创建规则。
4. 从笔记到任务、从任务到项目与专注时，保留来源链接和键盘焦点。

### P2：提高编辑与视图操作质量

1. 在现有 TipTap 文档模型上验证并增补 `/` 插入、块手柄、块转换、上下移动、键盘选择；先做常用块，再评估高级块。
2. 给任务/项目/日历的同一记录建立可复用的视图配置：筛选、排序、分组、显示属性及保存方式。
3. 明确详情的侧边预览/整页路径，避免每次打开任务都丢失列表位置。

### P3：把“不会丢”做成可感知的体验

1. 统一保存状态、撤销、回收站与恢复反馈；删除和批量修改必须有可理解的回退路径。
2. 对离线、跨设备同步和冲突处理做真实端到端测试，再决定是否增加版本历史。
3. 对大数据集搜索、长文编辑和视图切换测量输入响应；优化以测得的瓶颈为准。

多人实时协作、完整通用数据库构建器、权限系统属于另一组产品范围与数据架构决策。本轮按用户确认的个人工作流标准推进。

## 验收场景与建议门槛

以下是待实测与调整的目标值，不是当前成绩。

| 场景 | 验收门槛 |
| --- | --- |
| 任意页面捕捉任务 | 键盘可一键打开入口；输入并确认后可在任务页、项目页、今日视图找到同一条记录；焦点和成功反馈明确。 |
| 查找并续写笔记 | 能凭标题或正文定位，打开后光标可直接编辑；刷新后最新文字仍在；返回能回到原搜索上下文。 |
| 笔记转执行 | 从笔记生成任务时保留来源；项目归属、日期和状态在所有相关视图一致。 |
| 误操作恢复 | 完成、删除、移动、批量改动的反馈明确；可撤销或从回收站恢复；失败不静默。 |
| 键盘与辅助技术 | 核心旅程不用鼠标完成；焦点可见、菜单和对话框可退出、控件有名称与状态。 |
| 性能与可靠性 | 在固定样本数据上量化命令面板首开、输入到结果、视图切换和保存确认的 P95；先记录基线，再设阈值并阻止回归。 |

## 可借鉴的开源实现

- [BlockNote](https://github.com/TypeCellOS/BlockNote) 提供块拖拽、缩进、斜杠菜单和格式菜单，可作行为参考。它基于 TipTap/ProseMirror，和当前编辑栈相关；先评估增量集成与文档兼容性。官方仓库说明核心包多数采用 MPL-2.0，XL 包为 GPL-3.0，采用前逐包核许可证。
- [TipTap Drag Handle React](https://tiptap.dev/docs/editor/extensions/functionality/drag-handle-react) 是现有编辑栈的较小接入点；适合先验证块级直接操作。
- [AppFlowy](https://github.com/AppFlowy-IO/AppFlowy) 可参考视图和本地优先体验。其 Flutter/Rust 架构与当前 React/TipTap/Dexie 技术栈不同，适合作为交互案例而非整仓迁移候选。

## 当前结论

Focus&go 已有不少可用能力，关键工作是让它们在一条任务旅程中保持连续、一致、可恢复。达到 Notion 级别需要真实用户数据规模下的端到端验证和逐阶段改造；下方记录每轮已完成的改造及其验证边界。

## 2026-09-29 第一轮实施记录

- ⌘K 空搜索时显示最近打开的任务、笔记、日记和项目；从搜索结果或各模块直接打开均会记录，最多八条。记录按账户隔离，仅存类型与 ID，标题取当前数据；已删除的对象不会显示。
- 从编辑器按 ⌘K 打开面板后，使用 Escape 关闭会把键盘焦点还给原编辑位置。
- 从搜索结果打开笔记会将光标放到编辑区，包括当前已打开的笔记，便于直接续写。
- 定向 Vitest、TypeScript、ESLint 和 Web 生产构建通过；独立浏览器验证了搜索打开后再次显示、直接打开后显示、Escape 恢复编辑器焦点、搜索进入笔记后的编辑焦点，以及 1440px 与 390px 视口的面板宽度。
- 本轮尚未完成收藏、稳定对象深链接、跨视图上下文保持和大数据集性能验收；这些仍按 P1–P3 推进。

## 2026-09-29 第二轮实施记录

- 任务详情使用 `/tasks?task=ID`，笔记使用 `/note?note=ID`。列表点击和 ⌘K 搜索进入时会更新地址；直接打开、刷新、浏览器后退与前进可恢复对应任务抽屉或笔记编辑区。不存在的 ID 会从地址中移除。
- 关闭任务抽屉会清除任务参数；笔记切换、创建、移入回收站及删除时同步笔记参数。笔记链接打开时会清除当前标签与搜索筛选，以确保目标内容可见。
- 新增 `apps/web/e2e/object-links.spec.ts`，在独立浏览器数据中验证任务与笔记的刷新、后退、前进；两项测试通过。Web ESLint、TypeScript 与生产构建通过，`git diff --check` 通过。
- 本轮只覆盖任务页详情与笔记页的稳定链接。日记深链接、从跨模块跳转返回原筛选和滚动位置，以及完整工作流耗时验收仍待后续实施。

## 2026-09-29 第三轮实施记录

- 修正项目详情的笔记入口：新建或打开项目笔记使用 `/note?note=ID`，并附带受限的站内返回路径。笔记编辑器显示“返回项目”；项目的笔记标签和搜索词在 URL 中保留，返回后恢复列表滚动位置，并把焦点放回刚才的笔记卡片。
- 修正任务详情中“在笔记中打开”：它现在进入完整笔记编辑器，返回时重新打开来源任务详情；任务到专注页也带有“返回任务/项目”入口。对于日历等尚无任务详情深链接的来源，返回到全局任务详情。返回任务详情后焦点落在抽屉关闭按钮。
- 返回路径只接受站内任务页或项目详情页，避免外部或无关地址被当作返回目标。沿用现有 React Router，不增加依赖。可参考其 [navigate 与 location state 文档](https://github.com/remix-run/react-router/blob/main/docs/api/hooks/useNavigate.md)；项目列表使用自有滚动容器，因此单独保存位置。
- 新增返回路径单元测试和 `apps/web/e2e/return-context.spec.ts`。与第二轮对象链接测试合计五项 Chromium 浏览器测试通过，其中一项用独立样本数据验证项目列表滚动与焦点恢复；单元测试、TypeScript、全量 Web ESLint、Web 生产构建和 `git diff --check` 通过。独立浏览器另确认 390px 下返回按钮可见。
- 当前仍未覆盖日记深链接、所有模块的筛选与滚动恢复、任务与笔记间的来源关系建模，以及完整的个人工作流耗时验收；第三轮实现不代表达到 Notion 水平。

## 2026-09-29 第四轮实施记录

- 日记篇目使用 `/diary?entry=ID&view=day|week|month&date=YYYY-MM-DD`。从时间线或 ⌘K 打开后可复制地址，刷新及浏览器前进、后退会恢复对应篇目、日期和视图；无效篇目 ID 会清理。切换日期与视图时地址同步更新。
- 修复了新建篇目时旧地址的延迟副作用误清空选中状态、继而删除空白草稿的问题；也修复了连续快速新建两篇时，编辑器的缓冲文字可能写入另一篇或使前一篇被误删的问题。编辑器现在按篇目 ID 挂载，保存按篇目 ID 定位，空白草稿清理等待该篇保存完成后再判断；启动时的首次列表读取也不会用旧结果覆盖刚新建的篇目。
- 新增 `apps/web/e2e/diary-links.spec.ts`，覆盖立即创建与快速切换、两篇内容保留、前进后退、刷新、日期视图恢复、⌘K 搜索进入、编辑焦点及失效链接。与第三轮的项目/任务返回路径测试合计六项 Chromium 测试通过；Web ESLint、TypeScript、生产构建和 `git diff --check` 通过。
- 本轮验证的是独立浏览器中的本地数据与固定路径。完整个人工作流的点击数和耗时、大数据集性能、所有模块筛选/滚动恢复，以及跨设备同步可靠性仍需按 P0–P3 验收；不能据此宣称已达到 Notion 水平。

## 2026-09-29 第五轮实施记录

- 新增隔离的 `apps/web/e2e/personal-workflow.spec.ts`：构造 10 个项目、50 个任务、30 篇笔记，其中一篇含 400 段正文。测试从 ⌘K 捕捉任务，创建关联笔记并保存，再从 ⌘K 搜索找回、续写，返回任务进入专注，最后完成并撤销；同时核对笔记正文、专注关联任务及任务状态。
- 浏览器验收发现任务详情里的“完成”没有任务列表已有的“撤销”。任务详情现在也显示完成提示与撤销动作；撤销前检查任务仍为已完成，避免覆盖随后发生的状态修改。
- 联合回归还发现日记切换视图后立即使用浏览器后退时，地址和选中标签偶尔不同步；日记现在在 `popstate` 时直接应用浏览器当前地址。周/月视图后退场景连续五次通过，九项对象链接、返回路径和完整旅程浏览器测试一起通过。
- 一次本地 Chromium 自动化样本记录 19 次输入动作：捕捉约 0.9 秒，笔记往返与搜索续写约 5.8 秒，专注往返约 1.4 秒，完成与撤销约 1.7 秒；整段约 16.2 秒，其中样本播种约 2.2 秒。数值受本机启动、网络和 Playwright 等待影响，仅作可重复的回归基线，不代表真人操作速度或 P95 门槛。每次运行会把 JSON 附在 Playwright 测试结果中。
- 这是一条完整的个人任务旅程，尚未覆盖 P0 列出的其余旅程、手机宽度、中文/英文与主题矩阵、离线回放或大数据集 P95。对标 Notion 的最终验收仍未完成。

## 2026-09-29 第六轮实施记录
